#      the real line range (pitfalls §16.1: a stated range was wrong once).
#   2. Copy vanilla's WHOLE block programmatically (assert first line, last line
#      and the next key's line; braces balance).
#   3. Paste it here in place of the `<<< VANILLA BODY >>>` marker, uncommented,
#      and add the ONE marked `# EOTG` clause as a top-level child of the body
#      (an AND with vanilla; never inside a custom_tooltip shared with another
#      trigger, pitfalls §16.2). Use the vanilla block's own scope names for the
#      two cultures / two characters (pitfalls §16.3: never read a scope at top
#      level that vanilla only reads inside a guard).
#   4. Diff against vanilla: the only difference may be the `# EOTG` lines.
#   5. Keep THIS filename (differs from vanilla's, so it overrides by key and not
#      the whole file). Add the overridden keys to the CLAUDE.md benign list if
#      Tiger reports strict-scopes noise on the copy, and to the re-copy sweep
#      (pitfalls §2).
#   6. Confirm in game: logs/database_conflicts.log shows
#      "Overriding entry '<key>'" naming this file.
#
# Our clauses are always TRUE while the framework is off (no races registered)
# and under the permissive rule settings, so completing a stub is safe even
